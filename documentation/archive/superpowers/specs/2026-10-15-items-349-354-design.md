## 2. Alternatives

**A. Extend the current page (cheapest).** Add the missing targets, keep one table grouped by kind, keep tick-and-preview.
Does not fix the "which action will happen?" problem; no Primary Source concept.

**B. Mapping-first table with a per-row policy (recommended core).** One row per Monarch account with: status (Active/Closed),
**Maps to** (dropdown grouped like your CSV's App Location), **Policy**, Monarch value, App value, Difference, Action.
Policy has four values and is shown as a visible chip, never hidden in a menu:
`Auto-update` (Primary Source = Monarch), `Ask me` (default for new mappings), `App is source` (report only; Primary Source = App), `Ignore`.
The CSV seeds this table on first run.

**C. Exception inbox (recommended front door).** The page opens on **"Needs a decision (N)"**: only rows that differ and have policy Ask me,
each with three buttons: **Update app** · **Ignore this time** · **Always update** (sets policy to Auto-update). Everything else lives in
a second tab, **All mappings** (B). Unmapped Monarch accounts also appear in the inbox as "Map this account".

Recommendation: **B + C together**: B is the data model and the full table, C is the default view of it. It answers purpose 2 directly
(the three actions are the page) and purpose 1 (All mappings tab, plus an unmapped counter in the inbox).

## 3. Design

### 3.1 Targets (what an account can map to)
A registry of writable targets, each with a reader, a writer and an undo, extending `PLAN_TARGETS` in `src/reconcile.py`:
Accounts & Sources rows (as now); Other Asset Item rows (value + as-of date); liability rows; mortgage balance; note receivable face value;
income-stream `base` for annuities/pensions; Home value. Investment accounts stay report only. Every target declares its sign convention
(Monarch liabilities negative, app positive) and whether the figure is a plan-start anchor (warn before writing).

### 3.2 Closed accounts (recommended rule)
Monarch's closed flag already exists (stopped more than 3 days before the newest date). Rule:
- **Closed and last balance ≈ 0:** state *Closed, no action*. Hidden in a collapsed "Closed (n)" section, mapping kept (so history in the
  trends charts still attributes to the right app account), excluded from sums and from the inbox. No decision ever required.
- **Closed with a non-zero last balance:** shown in the inbox as "Closed with a balance. Moved elsewhere?" with **Mark done** (becomes Ignore).
  This catches a real money-moved-and-not-reflected case.
- **Reopened** (new balance appears): returns to Active automatically.
Alternative: auto-ignore every closed account. Simpler but silently drops the non-zero case; I do not recommend it.

### 3.3 Auto-update
Policy Auto-update applies at the end of the 04:00 import job, **using the same preview/apply/undo machinery and change log**, labelled
"auto" in the log. Safeguards: skip and surface in the inbox when the change exceeds a threshold (default 10% and $5,000) or when the
target is a plan-start anchor (home, mortgage) unless you opt that target in. A banner on the page and the dashboard says
"N values updated from Monarch since you last looked" with an Undo-all link.

### 3.4 Seeding from your CSV
One-time import button "Import mapping CSV" (also a script for tests): matches by normalized Monarch name, writes `monarch_account_map`
(kind/ref) and the new `policy` column, reports unmatched names and unresolvable App Field strings for you to fix by hand rather than guessing.
Schema change: add `policy` (and target ids for the new kinds) to `monarch_account_map`, via the same migration mechanism as the v13 tables.
Note the live `plan.rpx` is already at schema v13 only after its first run; another bump means one more irreversible upgrade, so I would
fold this into the same unreleased version if v13 has not shipped to your live plan (check before starting).

### 3.5 Item 350: remove the duplicate in Financial Reporting
What the reporter's Accounts table does that the app does not: account **type**, **per-chart inclusion** (Net worth / Holdings / Flows), and the
name-to-app mapping. Mapping is the true duplicate. Recommended split:
- The app's All mappings tab gains three read/write columns: Type, and the three chart-inclusion switches (defaults by type as today).
- The reporter drops the "Monarch accounts & mapping" table and the per-chart "Accounts ▾" editors; it **reads** type, mapping and
  inclusion from the app's data at import time (03:30 chain), and the chart rollover popups still list contributing accounts.
- Keep a small read-only "Accounts included" popover per chart so you can see what is in a total without leaving the page.
Alternative: delete only the table and keep the per-chart popovers as the editor for inclusion. Less work, but then inclusion is edited in one
place and mapping in another. Question 6 asks which you want.

### 3.6 Items 351–354 (root causes found in code)
- **351a.** `barChartSvg` draws the prior-year marker full bar height (`y-2`, length `barH+4`) but the budget marker half height
  (`y+barH/2`, length `barH/2+2`, `financial_trends_reporter/frontend/charts.js:328-329`). Make both the same geometry (budget stays orange, prior black).
- **351b.** `categoryListHtml` and `detailPopupHtml` draw only the spend bar. They need the same black/orange markers per row. Level-1 popup rows
  are categories, level-2 are merchants: confirm the backend has prior-year and budget per category and per merchant (it exposes them per tracking
  type today); if budget exists only per type, categories get prior-year only and I'll say so on the chart rather than invent a split.
- **352.** `filterByTimeframe` returns every row for "all" (`charts.js:52`), including plan-derived rows from before Monarch history, whose values sit on a
  different basis, and `lineChartSvg` plots a missing value as 0 (`y(p.value ?? 0)`, line 164) though the axis ignores nulls. Hypothesis: the pre-Monarch
  rows and/or nulls distort the range. **Diagnose with the real data first** (one screenshot plus the first/last 12 values), then frame the axis
  on the plotted range and break the line at gaps instead of dropping to zero. Not yet confirmed.
- **353.** Rename "Holdings value" / "Holdings" to **"Liquid Investments and Cash"** in `index.html` (heading, chart title, notes, popover title, table
  header) and `charts.js` titles/tooltips, then the tests and docs that assert the strings. The per-chart key `holdings` stays internal (renaming it would migrate stored toggles for no benefit).
- **354.** `Plan Data validation failed ... annual_appreciation_pct: expected percentage format ending with %; got '0'`. `schema_registry.validate_value`
  requires a trailing `%` for percent fields; the snapshot stored the field's before-value as bare `0`, and `revertToBuildHistoryEntry`
  (`frontend/js/dashboard_decomp_build_history.js:162-175`) replays `beforeStorage` verbatim. Fix at the replay and at the source: (1) format percent
  values by the row's type before sending (reuse the input cell's formatter); (2) find which edit path stored a bare `0` (likely the add-new-asset row
  default) and make it store `0.00%`; (3) regression test that reverts a snapshot containing a bare numeric percent. Needs a repro on a copy of your plan first.

## 5. Decisions (answered 2026-10-15)

1. **Page:** Inbox + All mappings (B+C).
2. **Auto-update:** at import, with guards (10% and $5,000; home/mortgage plan-start anchors wait in the inbox), logged, Undo-all.
3. **Closed accounts:** zero balance = silent and collapsed, non-zero = flagged in the inbox; mapping kept for chart history.
4. **Venmo:** truly ignored (excluded from the page and from the trends charts). Note this removes it from Liquid Investments and Cash totals.
5. **Annuities/pension:** Primary Source = **App**, so report only; nothing is written to the income stream. This changes the CSV's Monarch values for these five rows on seeding. Phase M2 drops the income-stream writer.
6. **350:** keep the reporter's per-chart Accounts popovers as the inclusion editor. Delete only the "Monarch accounts & mapping" table; account **type** and the name-to-app **mapping** are read from the app. Phase M5 shrinks accordingly (it no longer needs inclusion columns in the app).
7. **Other Asset Items:** an update writes value and as-of date together; basis never changes.
8. **Schema:** live plan is already v13, so the `policy` column is a new **v14** migration (irreversible for older app versions; back up `plan.rpx` first).
9. **Costco Visa:** credit-card liability row under Other Assets and Liabilities.
10. **352:** old plan-derived data at the left squashes the axis. Fix: frame the axis on the Monarch-era range when Monarch data exists and draw the earlier segment as a distinct, dashed line that is clipped to the axis or labelled "plan-derived" (confirm the look with one screenshot before finishing). Also break the line at gaps instead of plotting zero.
