## 2. Findings from read-only exploration (these shaped the design)

1. **345 root cause (high confidence):** `uploadYtdTransactions` in `frontend/js/dashboard_decomp_ytd_and_plan_folder_io.js:298-306` calls the API, reloads, and re-renders but never calls `markYtdTransactionsDirty()` (defined `dashboard_decomp_row_model.js:3590`, which sets `lastBuildOk=false`, `updateUnsaved()`, `setAppControls`). Other edit paths (lines 198, 212, 799) do call it. Same gap probably exists for delete-all (~line 314) and account-setup import.
2. **346:** the period is derived from a single server value, `ytdPeriodTargetYear()` → `ytdData.summary.current_year` (`…ytd_and_plan_folder_io.js:474`), and `ytd_summary()` already takes a `period` argument (`src/ytd_tracking.py:1247`). Import **keeps all years** ("Kept N row(s)… all years", `ytd_tracking.py:516`), so prior-year transactions already exist. Last-year wording lives at lines ~608, 654.
3. **347a:** the trends log has no prior-year or budget data today. `compute_snapshot()` (`financial_trends_reporter/trends_metrics.py:132`) emits only current-year `ytd_expense_hierarchy`. Adding two new fields is additive; **old log entries (22) will not have them**, so markers only appear for new snapshots unless we backfill (see D3).
4. **347b:** investment deposits/withdrawals are computed only as **aggregates** (`ytd_tracking.py:1448`, regexes at 127-128). No per-account split exists. Needs a new per-account breakdown that **reconciles to the existing aggregate**.
5. **347c:** `holdings.by_account` (per-account value, role, prior-year balance) exists in **all 22** log entries — the investments rollover is frontend-only. `net_worth` stores only aggregates (assets, home, other_assets, mortgage, liabilities), so a net-worth rollover can show **investment accounts by account + home/other/mortgage/liabilities lines**, but not per-account non-investment detail unless we log more going forward.

## 5. Design

### 345 — dirty flag
Call `markYtdTransactionsDirty()` after a successful upload/delete-all and `markYtdAccountsDirty()` after account-setup import. Prefer a small `afterYtdImport()` helper so future import paths cannot forget. Test: node frontend test asserting `lastBuildOk` false / Rebuild enabled after the upload handler resolves.

### 346 — year picker (owner decision: replace ALL spending-view this/last-year references)
Current mechanism: a two-button segmented toggle (`ytdActualsPeriod` = `"ytd"` | `"last_year"`, `…ytd_and_plan_folder_io.js:4,29-33`) plus server `summary.is_last_year`.

New: `ytdSelectedYear` state (default = latest year present in `ytdData.transactions`, fallback `current_year`). A `<select>` lists distinct valid years from the data, replacing the toggle. `ytdPeriodTargetYear()` returns the selected year; pass an int year to `ytd_summary(period=…)` (extend `period` beyond `ytd`/`last_year`; keep those values accepted for backward compatibility with saved state). `is_last_year` becomes `selected_year != current_year`. Semantics: **current year = year-to-date; any past year = full calendar year** (label it "Full year 2025" vs "2026 year-to-date" so the meaning stays clear). Persisted `ytdActualsPeriod` values map to years on load.

**D9 — Large Discretionary budget view follows the selected year (owner decision).** `dashboard_decomp_large_discretionary.js` uses `thisYear = new Date().getFullYear()` (line 170) for: `budgetThisYear` (171-175), the "In budget" column (196), and the footer note "This year's budget … (rows dated {year})" (199). Change these to the shared selected year, relabelled "{year} budget". Design rules:
- **Display-only.** The selected year drives what this page highlights and totals. It must **not** change the plan projection: each one-time row still projects only in its own year (inflated from today's dollars), never annualized. Before editing, grep the consumers of the #344 header Budget / domain total to confirm none feed the build; if any do, keep those on the real current year and show the selected-year total only in the page's own display (decision point → stop and ask).
- **Shared state:** move the selected year to a small shared getter (e.g. `selectedSpendingYear()`) read by both the Actual Spending panel and the Budget page; default = latest year in data, else current calendar year. The Budget page may be opened before Actual Spending, so the getter must not depend on that panel having rendered.
- **Visible cue** on the Budget page when the selected year ≠ the current calendar year (e.g. "Showing 2025") so a past-year selection is never mistaken for the live plan budget.
- Tests: update `tests/frontend/large_discretionary.test.mjs` (lines ~63-80, #344 assertions on "In budget", category detail sums and header Budget) to run for both the default year and a non-current selected year.

**Explicitly NOT changed (plan-year semantics, not the spending view):** `dashboard.js` help text at ~4055-6002 ("the last year you…", HSA, ACA, Roth, alimony, etc.), `planning_engines.py`, `hsa_schedule.py`, rental/projection stages.

Check the Python tests that read panel JS as text before editing (CLAUDE.md contract).

### 347b — investment net flows
Backend: extract per-transaction classification at `ytd_tracking.py:1448` into a per-account accumulator; emit `investment_net_flows_by_account` = `{account: {to_checking, from_checking, net}}`; **invariant test: Σ net == existing `net_ytd_investment_cashflow`**.
